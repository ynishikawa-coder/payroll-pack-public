# 確かめと仮

- 書く中身: 初期設定の照らし（過去の結果と人×項目で照らす本番の手順）・人×項目の突き合わせ・仮の 2 種類と必ず埋める 6 欄・全員が締まるまで待つ・仮の人を出さない
- 決定: ⟦鍵:給与計算/足りない時は仮で計算し出さない⟧・⟦鍵:給与計算/エンジンの共通化⟧（共通の物はオーナーの持ち物。違いは事務所の物＝給与ソフト〔出口〕と顧客の物＝勤怠ツール〔入口〕だけ）

この紙の語:

| 語 | 意味 |
|---|---|
| 答え | 過去に事務所が出した給与の結果（給与ソフトの明細・一覧表など）。正しいとは限らない |
| 初期設定の照らし | 初期設定で、法律どおりの計算と過去の支給控除一覧を人×項目で照らし、違う所を問いにすること。**本番の初期設定の手順**（芯には混ぜない・道具は `道具/答え合わせ/`） |
| 突き合わせ | 同じ支給月について、こちらの計算と給与ソフトの計算を人×項目で照らすこと。**本番**の確かめ |
| 仮 | 原本や値が足りず、見当の値で計算した値。仮が 1 つでも残る人は出口へ出さない |
| 見当 | 仮の値として置く値と、その拠り所 |
| 質問と回答 | 会社ごとの Drive にある問いと答えの台帳（`docs/設計/Drive の型.md` の型）。値を決める唯一の道 |
| 締め | 1 人の勤怠を確定した勤怠にし終えた事（年の台帳「締めの記録」が `締まった`） |

## 1. 初期設定の照らし（過去の結果と照らして決まりを聞き切る）

### 決めたこと
- **初期設定の照らしは本番の手順**（0 段の初期設定。会社の始めと決まりが変わった時。前は「開発の間だけ」としていた線を 2026-11-18 オーナーの決定で直した）。
  1. 規程・過去の支給控除一覧・勤怠の原本を受け取る（最初に計算する支給月の `1_届いた物/` に `書類_` で置く。`Drive の型.md` §2）。
  2. 決まりを MD とマスタへ起こし、パックで **法律どおりに** 計算する。
  3. 過去の支給控除一覧と **人×項目** で照らす（照らす道具は `道具/答え合わせ/`。照らし方は 2 の突き合わせと同じ人×項目の行）。
  4. 違う所を確認事項で事務所の担当者に聞く（「ここは実はこうですか」「ここが足りませんが大丈夫ですか」）。照らしの差は **初期設定の問いの種**（`設問.まとめる` の 4 つの箱の形・読み方の箱・会社×項目×向き で 1 つ・根拠つき）で返し、ほかの種と同じ `設問.まとめる` → `確認ページ.作る` の 1 本の道で聞く（照らし専用の問いの形を持たない）。答えを MD とマスタへ書き、2〜4 を違う所が全部説明できるまで繰り返す。
  5. 照らしで出た決まりのうち、パックの選べる式で表せない物は問いにせず、パックへ式を足す（3「仮の 2 種類」の②）。足すまでその会社を受けない。
- **芯は過去の結果を受けない・読まない・比べない。** 照らしは計算の本体に混ぜず、`道具/` の道具が芯の出した行と過去の一覧を並べるだけ。マスタ・台帳・計算の入力（マスタの値・マスタ・確定した勤怠）に答えの欄を持たない。
- **過去の資料で埋め切り、本当に分からない物だけ聞く**（2026-11-19 オーナーの決定（決定DB の行）。前の「過去の結果から逆算して決まりにしない」を置き換えた）。法律どおりの計算と過去の結果を人×項目で照らし、**差が 0 になった決まりと値は聞かずに決まり（MD・マスタ）へ書き**、出所に **過去の結果の照らし** を書く:
  - 形: `過去の結果 <支給月> <資料の名> <NO>:<項目>[・<NO>:<項目>…] 一致`（例 `過去の結果 2026.09支給 支給控除一覧表 000003:総支給・000003:残業手当 一致`）。項目は芯の項目の名。形の正本は `月次/例の確かめ.py` の `過去の結果を読む` の 1 か所（変更の記録の 書類の名・MD の［出所: …］・例の 確かめた人 の出所の全部がそこで読む）。
  - 一致は道具が確かめる: `道具/答え合わせ/出所を見る.py` が照らしの差の表（`照らす` の出す 差.json）と答えの行で、書いた人×項目の差が 0 で答えの出所がその資料かを 1 つずつ見る。差がある・照らしに無い・資料が違う・形が欠けた・照らしを渡さない物は止める（毎月へ進まない）。芯は過去の結果を見ないまま（照らすのは道具だけ）。
  - 差が 0 にならない所・過去の資料に表れない所（その月に起きていない場面の決まり）・過去の値どうしが食い違う所だけを問いの種にする。過去の結果から推し量っただけで一致を示せない見込みは、今までどおり問いに添える（`設問の作り方.md` §6.3）。
  - 形で書かずに答えの file の名を書類の名にした値（`（逆算）8〜10 月分の支給控除一覧表` など）は、どの人×項目の一致かが分からない＝今までどおり止める（照らしの形で書き直す）。
- 毎月は照らさない（毎月の確かめは 2 の突き合わせ。相手は給与ソフト）。

### 確かめ方
本物の会社を 1 社ずつ始める時、マスタの各値の「出所」が 原本・決まりの MD・質問と回答・過去の結果の照らし（人×項目で差 0）のどれかであり、照らしで確かめていない過去の結果を出所とする値が 0 であることを見る。照らしで出た違いの全部に、答え（質問と回答の番号）か、パックへ足した式の PR がある事を見る。
- 見る道具は `道具/答え合わせ/出所を見る.py`（呼び口 `python3 -m 道具.答え合わせ 出所を見る … --照らし 差.json`）。マスタ「変更の記録」の各行の 書類の名・問いの番号、決まりの MD の［出所］、例の 確かめた人 を見て、形で書かずに照らした答えの file を書類にした値・過去の結果の照らしの一致していない／資料の違う／形の欠けた値・答えの無い問いの見当が過去の結果の値・答えの無い問いを出所に確認済にした値・出所の無い値を 1 行ずつ返し、1 つでもあれば止める（毎月の計算へ進まない）。

## 2. 本番の確かめ（人×項目の突き合わせ）

### 決めたこと
- **照らす芯は 1 本**（`出口/` の突き合わせ）。給与ソフトごとに違うのは **読み口へ渡す形だけ**（給与ソフトの形は殻が事務所の設定から渡す・パックに製品ごとの読み口を置かない）。読み口は給与ソフトの出力を下の「人×項目の行」へ直すだけで、比べない。
- 項目の名は芯の項目の名にそろえる。給与ソフトの欄と芯の項目の対応は、**出口が給与ソフトへ取り込みを渡す時の対応と同じ 1 つ** を逆に引く（読み用の対応を別に持たない）。会社ごとの自由な欄の対応は、その会社の Drive のマスタ「項目」の給与ソフトの欄に 1 つだけ持つ。
- 二軸で走る: こちらは最後まで計算し、同じ値を給与ソフトへも渡し、給与ソフトの計算結果を受け取って照らす。

### 入れる物と出す物
人×項目の行（芯の出す物・読み口の出す物の両方がこの形）:

| 列 | 中身 |
|---|---|
| 支給月 | `YYYY-MM`（賞与は `YYYY-MM-賞与`） |
| 会社 | 会社の呼び名（`Drive の型.md` §1 の列「会社」と同じ字。型に会社の番号は無い） |
| NO | 社員の番号 |
| 項目 | 芯の項目の名（日数・時間・残業・総支給・差引・有給・欠勤・深夜・控除の各項目 …） |
| 値 | 数（円・日・時間。丸めは各々の決まりの後の値） |
| 出所 | 芯: 値の出どころ（原本の名か決まりの md の節か質問と回答の番号）／読み口: 給与ソフトの出力の file の名 |

突き合わせの出す表:

| 列 | 中身 |
|---|---|
| 支給月・会社・NO・項目 | 上と同じ |
| こちら | 芯の値（無ければ空） |
| 給与ソフト | 読み口の値（無ければ空） |
| 差 | こちら − 給与ソフト。片方が空なら「片方だけ」 |
| 差の見立て | 決まった語から 1 つ: `入力の違い`（給与ソフトへ渡した値と給与ソフトが使った値が違う）／`決まりの違い`（同じ入力で計算の決まりが違う）／`丸め`／`片方だけ`／`不明` |
| 差の出所 | こちらの値の出所（上の「出所」）。差の見立てを支える書類の名 |

- 差は **0 だけを一致** とする（許す幅を持たない。丸めの違いも差として出す）。
- 仮で外した人（3）は突き合わせない。表には出さず、月の数え方（下）で扱う。

### 差の流れ
- 差のある行は **質問と回答へ 1 問** にする（同じ見立て・同じ出所の差は 1 問にまとめる）。差を見てマスタや計算を直さない。
- 問いには「こちら・給与ソフト・差・見立て・出所」を載せ、答えで決まる物を書く:
  - こちらが違う → 答えを出所として決まりの md・マスタを直す（ふつうの直しの道。芯の不具合なら PR）。
  - 給与ソフトが違う → 事務所が給与ソフトの入力を直す（こちらは何も変えない）。
- 差のある人の納品は、その問いの答えが来るまで保留する（納品の元は今は給与ソフト。保留は事務所へ知らせるだけで、給与ソフトの操作はしない）。

### 毎月の流れのどこに入るか
`docs/毎月の流れ.md` の 2 段（給与計算・全員が締まった後に 1 回）の終わり。
1. 確定した勤怠・マスタの値・マスタ → 芯で計算（仮の印つき）
2. 出口の手前の関所で仮の人を外す（3）
3. 出口が給与ソフトへの取り込みを作る → 事務所が給与ソフトで計算
4. 給与ソフトの出力を受け取る → 読み口 → **突き合わせ**
5. 差 0 の人は納品へ。差のある人は問い（上）を出して保留
6. 月の状況に「突き合わせ」（下の月数）と「外した人」の数を書く

### 「差が N か月 0」の数え方（給与ソフトを外す条件）
- 会社ごとに数える。支給月（賞与も 1 回を 1 か月と同じに数える）が次の全部を満たす時、その月を「差 0 の月」とする:
  1. 突き合わせた全員の全項目で差が 0（「片方だけ」も 0 でない）
  2. その月の全員を突き合わせた（仮で外した人が 0）
  3. その月の差の問いを「給与ソフトが違う」で閉じた物が 0（給与ソフトが違った月は、こちらが正しくても差 0 に数えない。事務所の入力の直しが要った月だから）
- **続けて** 差 0 の月の数を数え、どれか 1 つが外れた月で 0 に戻す。
- N は事務所の設定（推奨 3）。数は管理表の「突き合わせ」の列に会社ごとに出す。
- 数の横に、その N か月で出なかった場面（入社・退社・賞与・年の変わり目・料率の変わる月）を「まだ見ていない場面」として並べる。外すかどうかは事務所が数と並びを見て決める（芯は判断しない）。

### 確かめ方（段階 3 の正しさの判定）
段階 3 では本物の会社を **1 社ずつ** 二軸で走らせ、この突き合わせの表をそのまま正しさの判定にする。1 社の判定は「全員の全項目の差が 0 か、0 でない差の全部に質問と回答の答えがある」こと。作り物の会社の一揃いでは判定しない。試験に置くのは国の率や表の例と回帰の見張りだけ（`tests/作り物/`）。

## 3. 仮

### 仮の 2 種類（分けて扱う）
「仮」は、見当の値で計算した値の印。中身は 2 つに分け、道を変える。

| 種類 | 例 | 道 |
|---|---|---|
| ① 事務所の担当者に聞けば埋まる物 | 勤怠が締まっていない・決まりがまだ確かめられていない・人の事実（扶養・保険の加入）が無い・その月だけの指示が要る | **問い**。確認事項で聞き、答えを反映先へ書いて埋める |
| ② パックが計算できない物 | パックに選べる式が無い・決まりを置く項目が無い | **問いにしない**。パックの直し（全社で選べる式・項目を足す PR）。何度聞いても埋まらないので、事務所に聞かない |

- ②は初期設定で見つけて、先にパックへ足してから始める（足すまでその会社を受けない）。毎月の計算で②が出たら、パックの穴としてパックを直す（その人は出さない）。
- 会社ごとの式は書かない。足す式は全社で選べる物にする。足すのは実際の会社で要った時だけ。

### 必ず埋める 6 欄（空なら計算しない）
次の 6 つは、空のまま既定で埋めると黙って額が違う。空の人が 1 人でもいれば、その月は計算に進まない（1 段の締めの照らしで拾い、①の問いで埋める）。

| 欄 | 中身 |
|---|---|
| 人の区分 | 社員・パート・役員・委託など |
| 源泉の欄 | 甲・乙・丙 |
| 保険の加入 | 社会保険・雇用保険の加入 |
| 労働時間の制度 | 通常・変形・フレックスなど |
| 扶養の数 | 源泉の扶養の数 |
| 保険料を引く月 | 当月・翌月 |

### 締めと計算の順（全員を待つ）
- 計算は、その会社の全員の材料が締まってから 1 回（`docs/毎月の流れ.md` 2 段）。仮の計算は試しの時だけ。
- **1 人でも締まらなければ、その会社の全員を待たせる**。締まっていない人だけを外して、ほかの人を先に出す事はしない。
- 締まった後の計算で仮が残る人（②など）は、下の関所で人ごとに外す。

### 値と人の印・関所
- **値ごとの印**: 芯は人×項目の各値に `状態` を持たせる。`確定` か `仮` の 2 つだけ。
  - 仮になる時: 原本が無い・値が空・原本（⑥の書類など）に「仮」とある・マスタの値の出所が質問と回答に無い（答え待ち）・**決まりの値が選べる値の外**（読めないまま黙って既定にせず、既定で計算して仮＋問い）。
    - 答え待ちの会社の値: 変更の記録の会社の行（NO が空＝会社か勤務の型の段の値）が、その支給月に効く行で 確かめ＝仮 なら、その値を自分の段で置いていない会社の全員を仮にする（`初期設定/段の解決.py` の `会社の記録の仮`。知らせに項目と問いの番号）。人の行の 確かめ＝仮 と同じ守り。
  - **表の照らし**: 選べる値の正本は `芯/設定の表.json` の 1 枚（使う所ごとに手書きで照らさない）。芯/集計（`一人を集計する`）と芯/計算（`要る値.確かめる`）は計算の最初に、読む全部の設定をこの表で照らし（`芯/設定.py` の `照らす`）、外の字は既定（無ければ見当）で数えてその人の **全部の値** を仮にする（効く項目を絞らない）。字の揺れ（空白・全角半角）は吸う。表に無い名は芯が読めない（試験で落ちる）。
  - 集計と計算の両方が読む名の外の字は、集計の問い 1 つにまとめる（集計の人の `設定の外れ`。計算は同じ名の問いを重ねない・その人は集計の状態が仮なので出ない）。
  - 道具/寄せ は表の外の字をマスタへ書く手順に出さず問い（`表の外の字`）にし、段の解決は外の字を知らせる（値は芯へ渡し、芯が仮＋問いにする）。
  - 仮の値には `見当`（置いた値）・`見当の拠り所`（何から置いたか。過去の答えから読んだならそう書く）・`問いの番号` を持たせる。
  - **1 人の読めない値で月を止めない**: 芯/計算 は、その人の計算の途中で値が読めない（式が無い・端数などの語が選べる値の外で `形の誤り`）時、例外を外へ上げずにその人だけ値なしの仮にし、同じ会社のほかの人は計算する（式が無い時は②＝事務所への問いにせずパックの直しの知らせ。読めない字は①の問い）。端数の語は手前（`芯/計算/要る値.確かめる` の `丸めの項目`）で既定の語に替えて仮にするので、多くは値なしでなく見当の額で出る。
  - 仮の値から計算した値も仮（総支給・差引など、仮を 1 つでも使った値は仮）。
- **人ごとの印**: 人の状態 ＝ その人の値に仮が 1 つでもあれば `仮`、無ければ `確定`。仮の数も持つ。
- **見当と確認の 1 問**（①の物だけ）: 足りない物 1 つにつき問いを 1 つ。同じ原因で何人も仮になる時は 1 問に人を並べる。問いの形:
  - 何が無いか（原本の名・項目）／見当とその拠り所／答えで変わる項目と人／答え方の例（「見当のとおり」「X 円」「原本を送る」）
  - 問いは芯が **返すだけ**。Drive の質問と回答へ書くのは各エージェントの repo（環境の口）。芯は Drive を開かない。
  - 芯の問いは種の 1 つ。初期設定 1 回・毎月 1 回で聞き切るための種の集め方・問いの 2 種類（会社の決まり・原本）と 4 つの箱・1 枚へのまとめ方（前半＝会社の決まり・後半＝原本）・答えの反映の照らしは `docs/設計/設問の作り方.md` が正本（`初期設定/設問.py`）。
- **出口の手前の関所**: `出口/` の入り口に 1 つだけ関所を置く。給与ソフトごと・出す物ごとに持たない。毎月は `月次.月を回す` が仮の人を寄せて関所へ通す（`月次/README.md`）。
  - 関所は人の状態が `仮` の人を、給与ソフトへの取り込み・明細・支給控除一覧・納品の全部から **外す**（印つきで出すことはしない）。
  - 関所より後ろ（取り込みを作る所・突き合わせ）は仮の人を受け取らない。
- **外した人の知らせ方**: 関所は「外した人」の一覧を返す（支給月・会社・NO・仮の数・待っている問いの番号）。エージェントはそれを月の状況の「外した人」の列と、事務所への知らせの頭に出す。出口の出す file には外した人の行も印も書かない。
- **仮が消える条件**: 問いに答えが来て、その答えを出所として原本・決まりの md・マスタが埋まり、計算し直した時に仮が 0 になった時だけ。
  - 「見当のとおり」も答え（出所は質問と回答の番号）。期限で急ぐ時は事務所がこの答えを出せば出口へ出る。
  - 答え・給与ソフトの値・突き合わせの一致では仮は消えない。
- **決まりの例の確かめ**: 給与のルール.md の例は、確かめた人 に `<答えた人の名>（<確かめの出所>）` を書いた例だけを確かめた例として数える（出所＝確認ページの答えの受付番号・決定DB の行〔日付と URL か鍵〕・回答のある問いの番号・過去の結果の照らし〔§1 の形。一致は 出所を見る が照らしで見る〕。誰が答えてもよい＝名簿は置かない・2026-11-19 オーナーの決定）。出所の無い例が 1 つでもある会社の月は出口へ出さない（`月次/例の確かめ.py`・`月次/README.md`「例の確かめ」）。

### 確かめ方
段階 3 の本物の 1 社で、原本を 1 つ抜いた月を走らせ、その原本に関わる人が出口の全部の file に 0 行であり、外した人の一覧と問いが 1 つずつ出ることを見る。答えを入れて計算し直し、その人が出口に出て突き合わせに入ることを見る。回帰の見張り（`tests/作り物/`）には「仮の人は出口の file に 0 行」の 1 つだけを置く。

## 4. 確かめの状態の語

値の状態は 2 つ、突き合わせの状態は別の軸で 3 つ。2 つの軸を混ぜない。

| 軸 | 語 | 意味 |
|---|---|---|
| 値の状態 | `確定` | 出所が 原本・決まりの md・質問と回答・過去の結果の照らし（人×項目で差 0・§1） のどれか |
| 値の状態 | `仮` | 上のどれでもない（見当で置いた） |
| 人の状態 | `確認済` | その人の値が全部 `確定` |
| 人の状態 | `仮` | `仮` の値が 1 つ以上 |
| 突き合わせ | `一致` | その人の全項目の差が 0 |
| 突き合わせ | `差あり` | 差が 1 つ以上（問いを出した） |
| 突き合わせ | `未突き合わせ` | 仮で外した・給与ソフトの出力がまだ来ない |

「確認済」に数える物と数えない物:

| 物 | 確認済に数えるか |
|---|---|
| 原本から読んだ値 | 数える |
| 決まりの md から引いた値 | 数える |
| 質問と回答の答え（「見当のとおり」を含む）を出所にした値 | 数える |
| 過去の結果の照らし（`過去の結果 <支給月> <資料の名> <NO>:<項目> 一致`・§1）を出所にした値 | 数える（`出所を見る` が照らしの差の表で差 0 を確かめた物だけ・2026-11-19 オーナーの決定） |
| **「過去の支給と一致」**（人×項目・資料・月を書かない前の印） | **数えない＝仮の残りに数える**。印そのものを持たない。Drive を新しい形で作り直す時に持ち込まない（照らしの形で書き直す） |
| 過去の答えから読んだだけで一致を示せない値 | 数えない（見当まで） |
| 給与ソフトの値と一致した値 | 数えない（突き合わせの軸の `一致` であって、値の状態は変えない） |

### 確かめ方
段階 3 の本物の 1 社で、人の状態の `確認済` の数と、値の出所が 原本・決まりの md・質問と回答 だけの人の数が同じであることを見る。
