# 入れてよい物（パックの線の正本）

- 書く中身: パックに入れてよい物と入れない物の線・見分け方・足りない物を見つけた時の道・置き場の表・線を守る 4 段（文・機械・人の目・合流）
- この紙が線の **正本の 1 か所** ⟦鍵:給与計算/入れてよい物の線の正本⟧。`CLAUDE.md`・`CONTRIBUTING.md`・PR の型・レビューは、ここを指す 1 行だけを持つ（同じ文を写さない）。

Javis・UTC のどちらの窓が、どちらの口から直しても、パックが同じ線で保たれるための紙。

## 1. 線（一言で）
**どの事務所でも同じ物はパックへ。製品・顧客・1 社の移行に結びつく物はパックに入れない（口だけパック・中身は事務所）。**

### 入れてよい物（どの事務所でも同じ物）
- 法と、法から出る共通の計算（芯の計算・集計）
- 関所（仮の人を出さない門・確かめの段）
- 法の表（`法の表/`。効く月の範囲つき）
- 入口と出口の **口の型**（表 A・表 B・月の数字の口・取り込みの形を受ける口。中身の値は殻が渡す）
- 1 か月を回す口（`月次/`）と、その部品の呼び順
- 一般の原本の形の読み口（例 日次の勤怠 CSV を「列名を渡されて」読む口。どの製品の名も既定の列名も持たない）
- 型（`初期設定/`）と、どの事務所にも当たる型の版の上げの直し（`道具/寄せ/直し/`）
- 規律・道具の自分の試験と、作り物の国の率や表の例・回帰の見張り（`tests/`）

### 入れない物
| 種類 | 例 | 行き先 |
|---|---|---|
| 製品ごと | 勤怠ツール・給与ソフトの名・列名・欄の並び・文字コードの既定・製品の名で選ぶ口 | 事務所の Drive（設定・つなぎ）を殻が読んで口へ渡す（`docs/設計/Drive の型.md` §4「製品ごとの値の置き場」）⟦鍵:給与計算/パックに製品ごとの物を置かない⟧ |
| 顧客ごと | 顧客の名・語・マスタ・台帳・実の勤怠・会社だけの区分の語 | 各事務所の Drive |
| 1 社の移行だけ | 1 社の前の道具の列の名・前の語の読み替え・その会社の過去の支給に合わせる答え | 事務所の Drive か、その事務所の殻（パックの直しにしない）⟦鍵:給与計算/移行だけの物はパックに入れない⟧ |

## 2. 見分け方
1. **法と共通の計算か**: 法の条・国の表・どの会社にも同じ式なら パック。
2. **製品・会社に結びつくか**: 名を出すと特定の製品・会社・事務所・側（窓の持ち主）が分かる物は パックに入れない。要るのは「口だけパック・中身は事務所の Drive の設定・つなぎ・殻」。
3. **別の事務所が明日この版を読んで、そのまま正しいか**: 正しくない（その事務所には当たらない・意味が無い）なら パックの物ではない。
4. 迷ったら入れない側に倒し、PR の本文に迷いを書く（§5 の合流へ）。

## 3. 足りない物を見つけた時の道
⟦鍵:給与計算/足りない物は口はパック中身は事務所⟧
- パックの **口** が足りない（どの事務所にも要る受け口・型の列・選べる値）: 口を足す PR をパックへ出す。中身（製品の列名・会社の値）は口に入れない。
- **中身** が足りない（その製品・その会社の値）: 事務所の Drive の設定・つなぎに書き、殻が読んで口へ渡す。パックへは出さない。
- 型を変える時は、どの事務所にも当たる型の版の上げとして直しを 1 つ添える（直しの json に `"当たる": "全ての事務所"`・`前の版`＝`版`−1・`初期設定/型.json` の `版` を上げる）。1 社のための読み替えは直しにしない。

## 5. 線を守る 4 段
1. **文**: この紙（正本）。`CLAUDE.md` の「給与のパック固有」・`CONTRIBUTING.md` §3 から 1 行で指す。
2. **機械**: 骨の自己検査 `tests/test_骨.py` の「4. 入れてよい物の線」⟦鍵:給与計算/パックの関所の機械の赤⟧
   - a. 製品の名の束（`tests/data/製品の名.txt`）が `.py`・`.json`・`.md`・`.html` と file・dir の名に出たら赤。md・html は `<!-- 例 -->`〜`<!-- /例 -->` の中を見ない（設計書の例の節だけ）。`CHANGELOG.md`（出した版の記録）は見ない。
   - b. 側の名の束（`tests/data/側の名.txt`。自分たちのアカウントと事務所の呼び名だけ）が `.py`・`.json` に出たら赤（設計書の地の文は見ない）。顧客の名はこの束に入れず、顧客の語の検査（`PAYROLL_NG_WORDS`／`PAYROLL_NG_WORDS_FILE`・語は repo に置かず CI の secret から渡す・`CONTRIBUTING.md` §3）に任せる。
   - c. `道具/寄せ/直し/直し_NNNN.json` の直しに `"当たる": "全ての事務所"` と型の版の上げの組（`前の版`＝`版`−1・`版` ≤ `初期設定/型.json` の `版`）が無ければ赤。印を持たずに通るのは、どの事務所にも当たると棚卸しした出た版の直し 2・4・5（中身は変えない）だけで、中身の指紋（`tests/test_骨.py`）が合う時に限る（版 ≤ 5 を名乗る新しい file・名の番号と版の違う file は赤）。直し 1・3 は便 2 で前の形の読み替えを外し、印を持つ（前の形の読み替えは事務所の Drive に置き、人の答えで渡す＝`道具/寄せ/README.md`）。
   - 外しの一覧は `tests/data/外し.json` の 1 か所（path ごと・`なぜ` と `畳む` が要る）。増やすのは PR の本文に理由を書いた時だけ。外した file が当たらなくなったらその行も赤（消し忘れを残さない）。今の外しは無い（便 2 で畳んだ）。
   - 束に語を足すのも PR で。顧客の語は束を repo に持たない（`CONTRIBUTING.md` §3）。
3. **人の目**: PR の型（`.github/pull_request_template.md`）の「種類」の欄（共通・口・製品・顧客・移行）と、レビューでこの紙に照らす（`CONTRIBUTING.md` §2）。
4. **合流**: この紙を変える PR と、Javis・UTC の窓で線の解釈が割れた PR は、オーナーの合意 1 つが要る（決まりの正本は `CONTRIBUTING.md` §2）。
