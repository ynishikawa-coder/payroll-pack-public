# 版（タグ）の出し方

## 版の名
- semver で `v<大>.<中>.<小>`（最初は `v0.1.0`）。
  - 大: 使う側が読み方を変えないと壊れる変更（入口・出口の形、マスタの型の互換が切れる）
  - 中: 互換を保った足し（新しい選択肢・新しい法の表の年）
  - 小: 直し（誤りの修正・文の直し）
- `v1.0.0` までは中の上げでも互換が切れることがある。その時は CHANGELOG の行の頭に「互換が切れる:」と書く（下の CHANGELOG）。

## CHANGELOG
- 記録は PR ごとに `CHANGELOG.d/<YYYYMMDD>-<話題>.txt`（枝 `claude/<YYYYMMDD>-<話題>` と同じ名）を 1 つ足して書く（書いた窓が足す。書き方の正本は `CHANGELOG.d/README.md`）。`CHANGELOG.md` の「未リリース」は決まった 1 行だけで、行を足すと赤（全部の PR が同じ所へ足すと、1 本入るたびに残りがぶつかり、取り込みが行を出した版の節へ紛れ込ませる事も起きた）。版を出す PR が `python3 scripts/changelog.py 版 vX.Y.Z YYYY-MM-DD` で断片を束ねて版の節にし、断片を消す。
- **殻が渡す形・呼び口・型の版が変わる PR は、記録の行（断片の行）の頭に `互換が切れる:` を書く**（`- 互換が切れる: …`）。殻が渡す形＝呼び口の入力・出力の鍵や値の単位（例 v0.1.2 の 有給 の `時間.週の所定` を分→時間の数・v0.1.3 の `源泉.報酬` を並び→1 つの値）、呼び口＝関数・CLI の口の名と引数、型の版＝`初期設定/型.json` の `版`。足すだけで前の渡し方がそのまま通る物（任意の鍵・出力の鍵を足す）は書かない。
- 過去の版の節は書き替えない（出した版の記録）。v0.1.3 までの節には `互換が切れる:` の印が無い（v0.1.2・v0.1.3 と型の版 2→5 で殻の渡す形が変わっていた）。v0.1.0・v0.1.1 は版の印だけで節が無い（今も足さない）。
- 骨の自己検査（`tests/test_骨.py`）が見る: 「互換が切れる」は行の頭の形だけ・型の版が 5 より上なら「型の版 N」の行に印がある・main からの枝で `tests/` の外の `.py`・`.json`・`.html` を変えたのに記録の断片を足していない（版を出す PR は `CHANGELOG.md` の版の節）・断片の形（`scripts/changelog.py check`）・AI の窓の枝で足す断片の名が枝の名と違う・版の印の在る節は、その印の時の CHANGELOG の同じ節と 1 字も違わない（見出しの日も。消す・印の時に無かった節を足すのも赤。印の無い節は一番新しい印より新しい版だけ）・版の印に入っている `道具/寄せ/直し/直し_NNNN.json` は、それを持つ一番新しい印の時の中身と 1 字も違わない（消すのも赤。直したい時は出した直しを替えず、新しい番号の直しを足す。比べるのは一番新しい印の時＝直し 1・3〔v0.1.7〕・直し 20〔v0.23.0〕のそれより前の書き替えは出した事実として受ける）。main や版の印が手元に無い時（浅い clone）は手元では skip、CI（履歴と印を全部取る）では赤。
- 版の節の見出しは `## [vX.Y.Z] - YYYY-MM-DD` の形だけ（例 `## [v0.1.2] - 2026-11-12`）。`## ` 見出しはこれと頭の `## 未リリース`（1 つ）だけ。日が抜けた・形が違う・暦に無い日の見出しは印を打つ道具に版として読まれず黙って印が付かないので、骨の自己検査（`tests/test_骨.py` の `版の見出しの誤り`）が赤にする。版は上から下へ下がり続け（同じ版を 2 度書かない）、日は上の版ほど前でない。

## 版を出す
版を出す PR を main へ入れる条件は、ほかの PR と同じく土台の核 §7 のとおり（ここに写さない）。版を出す手順（`python3 scripts/changelog.py 版 vX.Y.Z YYYY-MM-DD` で CHANGELOG の版の節を作って main へ入れると、印は main の CI がその commit で緑に終わった後に Actions が打つ＝CI が赤・まだ CI が見ていない commit に印は付かない。先の commit の CI が赤だった版は、同じ版の節を直す commit を入れると先が進む・`tests/test_版の印はCIの緑の後.py`）と印の決め方は、土台 agent-foundation-public の `docs/版の出し方.md`・`docs/版の印.md` に従う。
版を出す前に `python3 道具/法の表の見張り.py` を回し（終わりの値 0＝無し・1＝挙げた物が在る・2＝見張りが壊れた＝結果ではないので、標準エラーの訳で道具か表の形を直して回し直す）、改定の日が 90 日以内に来る・過ぎたのに行が無い法の表が挙がれば、その改定の行を足した PR を先に入れてから版を出す（国がまだ出していなければ親窓へ 1 行知らせる。docs/設計/法の表.md §3.4）。
読む土台の版の名は `.github/workflows/土台の版.json` の 1 か所にだけ書く（ここや CONTRIBUTING・workflow に重ねない。workflow はそこを直に読み、印を字で書くと `tests/test_土台の版.py` が赤）。鍵は 2 つ: `土台`＝確認ページの検査（qa-html の `check.mjs`・ci.yml）と公開の検査（`guard.py`・public-mirror.yml）／`版の印を打つ道具`＝tag.yml が読む `scripts/release/tags_from_changelog.py`（土台 v0.4.1 で畳まれたので、それが在る一番新しい v0.4.0 に留める。訳は同じ file）。土台の版を上げる時はそこを替え、手元の窓が入れている土台の版でも `QA_HTML_CHECK` を渡して試験を回す。

## 公開版へ出す
- UTC の窓はこの非公開の repo を読めないので、同じ中身を公開版 `ynishikawa-coder/payroll-pack-public` に置く。公開版の版の印はこの repo の印と同じ名で、中身も同じ（この仕組みの物と、公開版だけの検査の呼び口 `public-guard.yml` だけが違う）。
- 版の印を打つ `tag.yml` が終わると、Actions `public-mirror`（`.github/workflows/public-mirror.yml` → `scripts/public_mirror.py`）が回り、一番新しい印が公開版の一番新しい印より新しければ、その中身を noreply の名義の 1 commit で公開版の枝へ出す → PR → 公開版の必須の検査 `public-guard` の緑を待つ → rebase で合流（名義を書き替えない）→ 合流した commit に同じ印を打つ。
- push の前に、土台の公開の検査の本体（`guard.py`・版の印は `.github/workflows/土台の版.json` の `土台`）を公開版の main からの差に当てる。当たりがあれば push しない（公開版の枝は push した時点で誰でも読める）。当たりはこの repo の PR で直して新しい版を出す（出した版の中身は替えない）。同じ検査（中身の全部・版の印は同じ `土台`）を検査の入口 `scripts/check_all.sh` の段でも回す＝当たる字は PR の CI と手元で赤になり、main に入らない（顧客の語の照合は鍵を持つ公開版へ出す時が受け持つ）。
- 間の版は埋めない（一度に 2 つ印を打った時は新しい方だけ）。手で出す時は Actions の `public-mirror` を Run workflow で、`versions` に版の名を渡す（古い順に出す。公開版の一番新しい印より古い版は出さない＝公開版の main を古い中身に戻さない）。公開版の検査が落ちた回は、その PR と枝を閉じて消す。
- 運びの終わりに、公開版の一番新しい印（`git ls-remote`）がこの repo の一番新しい印と同じ名か、同じ名ならその印の木の中身（file ごとの中身と mode・持っていかない物と公開版だけの物を除く）が 1 つも違わないかを照らし、違えば `public-mirror` を赤で終える（印の名だけでは、公開版を手で直した・運びが一部だけ入った時に気付かない）（使う側は両側を別々に一番新しい印で読む＝ずれると計算のパックと給与エージェントの版が食い違う。v0.24.0〜v0.27.0 で起きた）。照らすのは一番新しい印だけで、間の版は埋めない決まりのまま。赤なら落ちた所を直して Run workflow で回し直す。
- 公開版の main の必須の検査 `check` で落ちて運べない類は、この repo の `check`（`scripts/check_all.sh` の試験）が先に見る: 今の木から公開の写し（持っていかない物を除き、印は飛び飛び）を組み、試験の全部を回す（`tests/test_公開版へ出す.py` の `test_公開の写しで試験の全部が通る`）。
- 公開版では CHANGELOG から印を打たない（`tag.yml` を持っていかない）。出していない間の版の印が、出した commit に付くのを防ぐため。
- 秘密（この repo の Actions の secret・値は書かない）: `PUBLIC_MIRROR_TOKEN`（公開版 1 つだけに Contents と Pull requests を書ける fine-grained の鍵）・`AF_DENY_BUNDLE`・`AF_DENY_WORDS`（顧客の語。公開版の secret と同じ値・公開版に在る方を置く）。公開版の設定で rebase の合流を許しておく。

## 給与エージェントの plugin
- 給与エージェントの部分（`plugins/payroll-agent/`）は、根の `.claude-plugin/marketplace.json`（名 `payroll-pack`）から plugin `payroll-agent` として配る。土台の plugin と同じ届け方（窓を開く前に、環境の setup script が user scope に入れる）。
- **版はパックの版の印そのもの**。`plugin.json` と `marketplace.json` に版を書かない（書くと `tests/test_給与エージェントの器.py` が赤）。計算のパックと plugin は同じ印を読む＝手順と計算の版が食い違わない。
- 両側とも公開版から同じ印で入れる（公開版は鍵なしで取れる。plugin と marketplace は公開版の持っていかない物に入らない＝試験が見る）。環境の setup script の行:

  ```bash
  claude plugin marketplace add ynishikawa-coder/payroll-pack-public#vX.Y.Z --scope user || true
  claude plugin install payroll-agent@payroll-pack --scope user || true
  ```

  入れ損ねを黙らせない書き方（入っていなければ窓が起動時に読む所へ知らせを書く）は土台の `docs/核の届け方.md` と同じ。版を上げる時は、この行の印だけを直す。
- 公開版へ出すのは版の印を打った後（上の「公開版へ出す」）なので、plugin の直しは印を打つまで両側へ届かない。

## 使う側
- 使う側（Javis・UTC の窓）は **版の印を読む**（main の先端を直に読まない）。今は両側とも一番新しい版の印（latest）を読む。
- 新しい版を読む時は CHANGELOG のその版の節を読み、`互換が切れる:` の行があれば殻の渡し方を合わせてから回す。
