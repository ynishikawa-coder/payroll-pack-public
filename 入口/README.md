# 入口

勤怠などの原本・勤怠ツールの出力を読み、`docs/設計/勤怠の形.md` の **表 A「日」・表 B「区間」**（月の合計しか無い時は 5 節の **月の数字の口**）へ直す部品。
芯（`芯/集計/`）はこの出力だけを読み、元の形を知らない。

守る線:
- **入口は Drive を開かない**。殻（各エージェントの repo の環境の口）が Drive から読んだ値（get_values の行・CSV の字・PDF から読んだ字）を渡し、入口は表を返すだけ。書き込むのも殻。
- **芯の数え方を出さない**: 深夜・残業・法定休日の時間・週 40 時間超・遅刻早退の分は出さない（勤怠の形.md §3）。原本やツールが自分で出した時間は表 A の「原本の時間」に照らす用として置くだけ。夜勤か・半休を何日と数えるかも決めない（事実だけを書く）。
- **勤怠ツールの名と列名はパックに置かない**（殻が事務所の Drive から渡し、部品の中で読み替えるだけ）。表 A・B には `原本の名前`（file の名）と `原本の種別`（勤怠の形.md の 5 つの語）しか出さない。
- **顧客ごとの物は repo に置かない**: 社員の名と NO・顧客だけの区分の語・ツールの番号と NO・列名の違い・集計表の列の対応は、事務所の Drive から殻が引数で渡す。部品は **形ごとに 1 つ**（会社ごとに作らない）。
- **読めない物は止めずに印を付けて返す**: 表 A の `読み取りの確かめ＝要確認`、`結果.要確認` に理由。要確認が 1 つでも残る人は `結果.人の状態()` で `仮` になり、出口へ出ない ⟦鍵:給与計算/足りない時は仮で計算し出さない⟧。
- 答え合わせ（過去の支給との照らし）はここに入れない。

## 1. 口の型（どの部品も同じ）

```python
from 入口 import 口
c = 口.文脈(支給月="2026-11", 会社="<会社の鍵>", 期間の始め="2026-10-21", 期間の終わり="2026-11-20",
           社員={"<勤怠の表記>": "<NO>", ...},        # マスタ①社員 の 勤怠の表記 → NO
           休日={"2026-10-25", ...},                  # 会社の暦（会社の決まり 時間.暦）で休日の日付
           区分の読み替え={"<顧客だけの語>": "有給"},   # 既定の区分に無い語（事務所の Drive に置く）
           つなぎ=[...],                              # マスタ⑥つなぎ の行（勤怠ツールの番号 → NO）
           # ↓ 人ごとの前提（どれも任意。鍵は NO か 勤怠の表記）
           人の型={"<NO>": "<勤務の型の鍵>"},          # 表 A の 勤務の型 へ置き、型の休日 を引く
           型の休日={"<勤務の型の鍵>": {"2026-10-31"}},  # 型ごとの休み（例: 月〜金の型の土曜）
           人の休日={"<NO>": {"2026-11-13": True}},    # その人だけの会社の休み（例: 別の現場の夏の休み）
           人の区分={"<NO>": "委託"},                  # マスタの 人.区分
           所定の無い人={"<NO>"},                      # 人.区分 のほかに所定の無い人
           勤怠を取らない人={"<NO>"},                  # 勤怠が無いのが正しい人（役員）
           出勤簿が無い={"<NO>": 480})                 # 時間.出勤簿が無い の人 → その人の日の所定時間（分）
r = <部品>.読む(<殻が渡す原本の値>, c, ...)
r.日        # 表 A の行（dict・列は 口.表Aの列 の順・値は字）
r.区間      # 表 B の行（口.表Bの列）
r.月の数字  # 月の数字の口の行（口.月の数字の列）
r.月の変動 / r.人ごとの支給控除   # 手当・控除の書類の行き先（Drive の型.md §4）
r.要確認    # {NO, 勤怠の表記, 日付, 理由}
r.人の状態()  # NO → 仮／確定
```

| 物 | 中身 |
|---|---|
| 入力 | 殻が渡す原本の値（部品ごとに下の表）と `文脈`。期間と休日は殻が会社の決まりから出して渡す |
| 出力 | `結果`。日の部品は **期間の全部の日に表 A の行を 1 つ**（勤怠の形.md §1）。区間は 1 から番号。時刻は `h:mm`・日またぎは 24 を足す |
| 読めない時の印 | 表 A の `読み取りの確かめ`＝`要確認`・`結果.要確認` の理由。原本に無い日＝印 `原本に無い`（休日なら 休日・そうでなければ 欠勤）。打刻抜け＝表 B の終わりを空・印 `打刻抜け`。NO が引けない人＝NO を `仮:<勤怠の表記>`（空にしない）。人は `仮` |
| 形の検査 | `口.形の検査(表Aの行, 表Bの行たち)`（勤怠の形.md §2 の決まり）。全部の部品の出口で回し、外れた日は要確認。芯の入口でも同じ物を回してよい |
| 重ねる | `口.重ねる(基, 上)`: 上に在る人×日の表 A・B を置き換える（例: 出勤簿の上にメールの連絡）。読む順は作業のルール「読み方と合わせ方」 |

人ごとの前提で変わる所（`口._一日`）:
- **休日の 3 段**: `文脈.休日か(日付, NO)` は 人の休日 → 型の休日（人の型 で引く）→ 会社の 休日 の順に見て、狭い方が勝つ。段の値は日付の set（その日は休日）か `{日付: True／False}`（書いた日だけを決める。False＝その段では勤務日）。会社の 休日 だけを渡す呼び方は今までどおり。
- **出勤簿が無い人**（`時間.出勤簿が無い`）: 区分も時刻も無い勤務日（原本に無い日を含む）は 日の種類＝勤務・印 `定時扱い`・時刻の無い労働時間＝所定時間・備考「出勤簿が無い（所定どおり働いたとみなした）」。要確認にしない。所定時間が渡されない時だけ要確認。書かれた区分・時刻はそのまま読む。
- **勤怠を取らない人**（`文脈.勤怠を取らない人`。初期設定の入口の文脈が `人.区分`＝役員 の人を渡す）: 空のタブ（どの日も時刻・区分・印・備考が無い）はその人を表 A・要確認に出さない（勤怠が無いのが正しい＝芯/集計 が確認済にする）。1 日でも書いてあれば今までどおり読み、空の日は 日の種類＝休日・備考「勤怠を取らない人の空の日」（欠勤・要確認にしない）。入口は区分の名を知らない（殻が決めて渡す）。ほかの人の空のタブ・空の勤務日は今までどおり要確認。
- **所定の無い人**（`人.区分`＝委託 か 所定の無い人）: 区分も時刻も無い日（原本に無い日を含む）は 日の種類＝休日・備考「所定の無い人の空の日（働いていない日）」。勤務日に数えず要確認にしない。働いた日はいつも 勤務（休日勤務にしない）。
- **年休の日に勤務の時刻もある日**（区分「有休」などに出退の時刻・実働も書いた日＝半日の有休と勤務を 1 日に書いた形）: 日の種類＝勤務・休暇の種類＝年休・区間はそのまま。単位は原本から決める: 休暇の時間がある＝時間／労働の区間が全部 12:00 から後（日をまたがない）＝午前半休／全部 13:00 までに終わる＝午後半休（備考「年休の日に勤務の時刻がある（…＋勤務と読んだ）」）。決まらない日（全日の時刻・昼をまたぐ短い時刻・時刻の無い労働時間だけ・打刻抜け）は単位を空にして要確認（黙って全日にも半日にもしない）。休日・所定の無い人の日と、代休など年休の外は今までどおり。区分の読みは `口._一日` に寄るので、どの読み口も同じ。

既定の区分の語（`口.既定の区分`）: 出勤・休日・公休・所定休日・法定休日・休日出勤・休出・欠勤・有給・有休・年休・午前半休・午後半休・代休・振休・振替休日・休職・休業・遅刻・早退・定時扱い・在宅・出張・直行直帰 など一般の語だけ。これに無い語は `区分の読み替え` が無ければ要確認。

## 2. 部品の一覧と選び方

原本の **形** で選ぶ（会社では選ばない）。1 つの月に形が複数あれば、それぞれで読み `口.重ねる` で合わせる。

| 届いた物 | 部品 | 殻が渡す物 | 出す物 | 原本の種別 |
|---|---|---|---|---|
| 紙のタイムカードの PDF・画像（印字・手書き・黒塗り） | `PDFタイムカード.読む(カードたち, 文脈)` | カードごとに {勤怠の表記, 原本の名前, 見出し, 行}。欄の字は読んだまま（`(手)`＝手書き・`■`/`黒塗り`/`取消`＝入れない・1 欄に 2 つの時刻はそのまま） | 表 A・B | PDFタイムカード |
| 先方の Excel・スプレッドシートの出勤簿（日ごとの時刻） | `Excel出勤簿.読む(表, 文脈)` | {原本の名前, 見出し, 行}（get_values のまま。時刻は `8:00`・`8:00:00`・Excel の小数）。何人も並ぶ表は見出しに 氏名、1 人 1 枚は 勤怠の表記 を渡す。色・コメントは殻が字にして 備考 の欄へ | 表 A・B（「実働」「労働時間」の欄は 原本の時間 の 総労働。時間数＝印字の 退−出 とは別） | Excel出勤簿 |
| 勤怠システムの月報（人ごと・文字が取れる PDF） | `勤怠システムの月報.読む(月報たち, 文脈)` | 月報ごとに {勤怠の表記, 原本の名前, 見出し, 行}。`*`＝手修正・`!`＝打刻エラー はそのまま | 表 A・B（所定内・深夜・実働は 原本の時間） | 勤怠システムの月報 |
| 勤怠ツールの日次の CSV（1 行＝1 人×1 日） | `日次の勤怠CSV.読む(...)`（下の 3 節） | CSV の字・原本の名前・文脈（つなぎ）・道具（⑥つなぎ の呼び名）・列名（任意。無ければ つなぎ から） | 表 A・B | 勤怠システムの月報 |
| 人ごとの月の合計だけの表 | `集計済み勤怠表.読む(表, 文脈, 列の対応, 時間の書き方, 見ない)` | 表と、見出し → 5 節の項目の語の対応（作業のルール「読み方と合わせ方」に置く）・`60進`/`10進`（マスタ③会社 の 時間の書き方） | 月の数字の口 | 集計済み勤怠表 |
| メール・メモ・電話の聞き取り | `メールとメモ.読む(連絡たち, 文脈, 項目の辞書, 単価)` | 1 件 1 つの連絡（勤怠: 勤怠の表記・日付・区分・出・退… ／ 手当控除: 手当控除の一覧と同じ） | 書かれた日だけの表 A・B（`口.重ねる` で上から重ねる）・月の変動 | メールとメモ |
| 手当・控除の一覧（寮費・弁当代・組合費の書類） | `手当控除の一覧.読む(行たち, 文脈, 原本の名前, 項目の辞書, 単価)` | 行 {勤怠の表記 か NO, 項目, 額 か 個数, 適用開始?}・マスタ④の項目の辞書（項目 → 毎月同じか）・単価 | 月の変動（毎月変わる額）・人ごとの支給控除（毎月同じ額） | —（表 A・B でない） |

選び方の迷い:
- **先方が作った集計**は原本（集計済み勤怠表で読む）。**事務所が手で作った集計**は答えなので入口で読まない（答えの根・開発の道具だけ）。
- 日ごとの打刻と集計済み表の両方が来る会社は、日の部品で表 A・B を作る（芯は日から出し直す）。日の記録がある人の集計済み表は読まない（照らすのは段階 3 の開発の道具）。日の記録が無い人だけ集計済み表から月の数字の口で入れる（片方が無いことで止めない）。
- 入退社・決まりの変更の連絡は入口で読まない（マスタ「変更の記録」と質問と回答の道）。
- 新しい形の原本が来たら、まず既存の部品の 見出しの読み替え（表の `読み替え`）で読めないかを見る。読めない時だけ形の部品を 1 つ足す（会社の名の部品は作らない）。

## 3. 勤怠ツールの日次の CSV の読み口

パックは勤怠ツールの製品の名・既定の列名を持たない（⟦鍵:給与計算/パックに製品ごとの物を置かない⟧）。どのツールの書き出しでも「列名つきの日次の勤怠 CSV（1 行＝1 人×1 日）」の 1 つの部品で読み、ツールごとの違い（呼び名・見出しの字・人の番号）は事務所の Drive のデータとして殻が渡す。

| 部品 | 人の結び方 | 列 |
|---|---|---|
| `日次の勤怠CSV.読む(csv字, 原本の名前, 文脈, 道具, 列名=None)` | `文脈.つなぎ` の 側＝入口・道具＝<道具>・NO 有り の行の「その道具での番号」→ NO。無ければ 氏名 を 勤怠の表記 で引く。どちらも無ければ `仮:` | 役 → 見出しの字。`列名` を渡さなければ `文脈.つなぎ` の 側＝入口・道具＝<道具>・**NO 空** の行（その道具での番号＝`列.<役>`・その道具での名＝見出しの字）から引く。役は 番号・氏名・日付・区分・出・退・休憩・外出・戻・実働・深夜・残業・備考（番号・日付・出・退 は必ず）。足りなければ止まる（既定の列名で黙って読まない） |

- 道具の呼び名・列名・ツールの番号と NO・顧客だけの勤務区分の語は、事務所の Drive（マスタ⑥つなぎ・区分の読み替え）に置き、殻が渡す（置き場は `docs/設計/Drive の型.md` §4「製品ごとの値の置き場」）。
- ツールが出した実働・深夜は 原本の時間（照らす用）。「残業」は法定内か法定外かがツールの設定で変わるので 5 節の語へ寄せず備考へ。
- 日次の CSV で読めない形のツールが来たら、まず列名で読めないかを見る。読めない時だけ **形の** 部品を 1 つ足す（製品の名の部品は作らない）。

## 4. 勤怠のシステムへ入れた差分の形

事務所が先方の勤怠のシステムへ手で入れ直した事（打刻の直し・区分の付け替えなど）を残す形。**芯の入力にしない**（芯は表 A・B だけを読む）。照らす・知らせるための記録。

- 置き場: `10_月ごと/<YYYY.MM支給（M月分）>/02_加工/` に頭 `勤怠の差分_` を付けて置く（例 `勤怠の差分_20261108_打刻の直し`）。1 つの月の差分は 1 枚にまとめてよい。
- 1 行＝1 人×1 日×1 つの値の直し。列（この順）:

| 列 | 値の形 | 意味 |
|---|---|---|
| 会社 | 字 | 会社の鍵 |
| 支給月 | `YYYY-MM` | |
| NO | 字 | マスタの NO |
| 勤怠の表記 | 字 | 照らす用 |
| 日付 | `YYYY-MM-DD` | 表 A の日付（勤務が始まった日） |
| 表 | `A`／`B` | どちらの表の値か |
| 区間の番号 | 数 | 表 B の時だけ |
| 列 | 字 | 表 A・B の列名（勤怠の形.md の語。ツールの列名でなく） |
| 前の値 | 字 | システムに入っていた値（空も可） |
| 新しい値 | 字 | 入れ直した値 |
| 理由 | 字 | なぜ直したか（先方の連絡・原本との照らし など） |
| 出所 | 字 | 拠り所の原本の名（01_原本 の file の名） |
| 入れた日 | `YYYY-MM-DD` | システムへ入れた日 |
| 誰が | 字 | 入れた人 |

- 差分を入れた後のシステムの書き出しを入口がもう一度読み、表 A・B を作り直す（差分を表 A・B に足し込む道は作らない）。

## 5. 部品の置き場

```
入口/
  口.py                 口の型（文脈・結果・列・値の読み方・形の検査・仕上げ・重ねる）
  _日の表.py            日ごとの時刻の表を読む共通の手（PDF・Excel・月報が使う）
  PDFタイムカード.py
  Excel出勤簿.py
  勤怠システムの月報.py
  集計済み勤怠表.py
  メールとメモ.py
  手当控除の一覧.py
  日次の勤怠CSV.py      勤怠ツールの日次の CSV（列名と道具は殻が渡す）
```

試験は `tests/入口/`（作り物の小さな原本 → 表 A・B が黙って変わらない見張りと、読めない物が要確認・仮で返ること）。Python 3 の標準ライブラリだけ。
